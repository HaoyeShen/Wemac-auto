# 后台图片、附件与分享内容读取

微信侧的消息监听、文件下载、加密缓存读取和回复发送均通过固定版本的内部函数完成。处理图片、附件及网页不需要激活微信窗口或手动点开消息。当前固定版本为 Apple Silicon 微信 4.2.0（270348）；其他版本必须重新核对函数指纹。

## 图片与动画修复

- 图片消息不再把包含 CDN 凭据的 XML 当作图片内容交给模型。
- 原生资源库用消息服务器 ID 和聊天 ID 核对资源，不通过相似文件名寻找图片。
- 已缓存的 V2 文件调用微信自己的解码函数；未缓存的图片调用微信 C2C 下载入口，并等待绑定本次请求 ID 的原生完成回调。
- 微信 CDN 可能把 WXGF 源返回为兼容 JPEG，不能要求 JPEG 的 MD5 等于原始 WXGF 的 MD5。下载结果核对原生完成状态和请求身份，缓存记录源消息摘要及输出 SHA-256。
- WXGF 即使 MD5 匹配，也必须再调用微信的图像编解码器转换。旧实现曾直接返回此格式，使 Pillow 无法读取；静图现保存为 PNG，动画保留多帧。
- 识图请求保留清晰画面和 `detail=high`。动画按播放时间抽样，最多六个视图；长截图附带可读局部。一个模型请求最多八幅图，并标注它们属于哪个附件。
- 图片追问按当前会话及发送者关联。新图读取失败时不拿旧图代替；普通新话题不自动附上旧图。原始资源本身分辨率低时，不把放大当成新增细节。

## 文件正文

机器人接收文件卡片后，从原生 XML 取得附件元数据，通过内部 CDN 下载文件。支持 TXT、Markdown、CSV/TSV、JSON/JSONL、常见代码/配置文本、DOC、DOCX、RTF、PDF、PPTX、XLSX。

DOCX 提取正文、表格段落、页眉页脚及脚注，并可把嵌入图片交给视觉模型。DOC/RTF 调用 macOS 自带转换器，不打开 Word、不执行宏。Office 和 PDF 在独立进程中解析，处理超时或解析崩溃不会带走微信或机器人窗口。

单个附件上限 32 MiB；压缩包解压总量上限 64 MiB；提取正文上限 20 万字；单轮模型输入使用有标记的正文或相关节选。不会把节选称为全文，也不会自动将新收到的文件加入跨聊天共享训练资料。加密文档、扫描 PDF 无可提取文字等情况会明确返回不可读状态。

## 公众号和视频号

分享卡片及其内链从微信原生消息中读取。公开 HTTPS 资源使用微信自身的 HTTPS 下载入口；公众号正文识别 `js_content`，排除导航、脚本与页脚，正文不可见或要求验证时不会把标题当全文。

视频号卡片具有可读取媒体地址且视频可解码时，原生下载实际媒体，再由隔离的本地进程抽取最多五个视频帧和前 120 秒音轨。模型收到实际画面和成功取得的音轨转写；没有取得音轨时不能推断对白。视频号的账号鉴权、过期地址、额外媒体加密可能使实际视频不可读，此时只能明确标注已读取的卡片信息及封面，不能声称看完视频。

**角色语音合成仍使用本地 GPT-SoVITS。视频音轨识别使用已配置的 DeepSeek ASR API，属于云端文字识别。** 图像理解同样使用当前配置的视觉模型。[DeepSeek 视觉接口说明](https://api-docs.deepseek.com/guides/vision/)、[音轨识别说明](https://api-docs.deepseek.com/guides/asr/)。

## 原生入口与生命周期

| 能力 | 此版本入口偏移 |
| --- | --- |
| V2 缓存文件解码 | `0x4c77c34` |
| C2C 图片/文件下载 | `0x5c201c8` |
| HTTPS 资源下载 | `0x5c207ec` |

偏移不是单独的兼容保证。连接时核对核心文件及函数指令；下载桥另核对 SHA-256。异步回调由 `RTLD_NODELETE` 原生 C++ 桥持有，完成通知不进入 JavaScript/Python 回调；宿主超时或断开时不释放仍在使用的对象，也不自动重新提交不确定的请求。

SDK：`session.download_media(message, directory)`、`session.download_attachment(message, directory)`、`session.download_public_resource(url)`。旧 profile 可运行 `research/build_cdn_download.py --profile /path/profile.json` 更新固定版本目录及独立辅助库；此脚本不改动、签名或重启当前运行的微信。

## 本机验证

2026-11-16 完成原生后台验收：两张真实消息图片（534×730、1276×1576）、十帧表情、未依赖窗口的 C2C 图片下载、约 19 MB PDF 附件下载及 53,479 字正文提取。当前视觉模型准确读取实际测试图片里的英文、质谱主题、照片内容和表情文字。独立视频验证完成原生 HTTPS 下载、五帧提取和音轨识别。另用固定图案验证了图像确实进入模型，而非仅传入文件名或 XML。

本机两条历史公众号链接触发访问限制，未取得正文；没有将它们记作成功读取。验证过程没有退出或重启 WeChat-Wemac。

## 2026-11-17：原生表情与缓存前缀修复

原生同步事件可能早于本地表情缓存写入。缓存不可用时，现在调用微信内部 HTTPS 函数读取消息的原始 CDN 资源，严格核对消息 MD5，然后转换 WXGF；不以缩略图替代原图。“这是啥”“这是什么”等追问会关联近期同一发送者的附件，读取曾失败时按精确原生消息 ID 恢复。

模型请求把固定人格与工具协议放在变化的收件人、检索资料和会话状态前面，并稳定排列表情目录。不复用生成的答案，不跨聊天共享上下文，也不删除本轮资料。服务端真实回报的缓存命中/未命中 tokens 继续用于统计，缺失数值保留为未知。

一次真实 DeepSeek 控制验证中，更换收件人与检索资料后，命中 2,816/3,090 输入 tokens；随后一次为 2,944/3,090。这是样本结果，不是长期命中率承诺。前缀匹配和缓存持久化由提供方决定，见 [DeepSeek 缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。

## Word 正文与本地资料检索

修复了当前 Word 正文在组装模型请求时被普通聊天历史预览（1,600 字）再次截断的问题；当前附件保留有界的正文证据，长文仍标明节选。无扩展名的文件卡片根据原生 fileext 识别；DOC/DOCX/RTF 根据真实容器签名分辨，兼容 Strict Word XML。追问下载未完成的文件时，只按当前会话、发送者和精确消息 ID 恢复。

本地 JSON 资料改为逐层解析嵌套对象，避免已读到来源元数据后跳过后续角色 facts。保留字段名与数值；中文两字词增加独立召回，结构化姓名字段优先于导出聊天中的偶然匹配，检索片段保留资料名称与编号。它属于本地检索增强，不是改写模型权重。

验收覆盖历史预览之后的 Word 关键字段进入实际模型、无文件后缀的原生消息适配、中文姓名在大量噪声候选中的召回和来源标记。授权本地 Word 样本中四份成功提取正文，一份未提取到可用正文，明确返回不可读状态。未使用新的微信入站 Word 消息进行人工验收；最近查询的原生历史未包含 Word 附件。
