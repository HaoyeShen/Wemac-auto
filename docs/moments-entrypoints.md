# 朋友圈发布、点赞与评论入口定位

日期：2026-11-12。目标为 macOS arm64 微信 4.2.0（build 270348）。
本文前两阶段保留离线定位证据。2026-11-13 后续已加入原生接口：朋友圈列表和单条详情
实际读通，四种写入请求完成原生编解码检查；发布、点赞、取消点赞和评论默认关闭，
尚未执行服务器写入验收。当前用法与限制见 [原生接口用法](native-api.md)。
所有地址都是 `Contents/Resources/wechat.dylib` 内相对偏移；实际地址为模块加载基址加偏移。
本次仅离线读取已安装程序的代码，没有附加探针、调用目标函数、发布、点赞或评论。

## 发布流程：高可信静态候选

```text
0x3ba1c5c（上游调用者，具体业务角色尚待核对）
  -> 0x3afea48（DoPublishIfNeed 日志名）
      -> 0x3afce60（发布协调流程）
          -> 0x3afee30（PreprocessVideo 日志名；条件分支）
          -> 0x3aff550（SendPostRequest 日志名）
              -> 0x3b00e60（请求包装层）
                  -> 0x3b02080（请求描述构造器）
```

证据：

- `0x3afeaf4` 读取完整的 `DoPublishIfNeed` 字面量，所在函数起点为 `0x3afea48`。
- `0x3afedc8` 直接调用 `0x3afce60`。
- `0x3afd490`、`0x3afd91c` 分别调用预处理与 SendPostRequest 候选函数。
- `0x3afff1c`、`0x3b00284` 读取完整的 `SendPostRequest` 字面量。
- `0x3affc94` 直接调用请求包装层；`0x3b010d4` 直接调用描述构造器。
- 静态还原描述构造器中的字符串初始化代码，得到
  `/cgi-bin/micromsg-bin/mmsnspost`，命令号 **209**。

另一个直接使用相同发布描述构造器的请求构建／提交候选为 `0x3b037f8`。

这比仅搜索函数名提供了更完整的静态证据，但尚未验证参数、对象上下文、线程及回调。
不能直接把业务函数包装为 `void publish(char*)`；上层代码包含共享对象、任务状态及
异步结果，具体 ABI 必须进一步核对。

## 第二阶段：请求结构、动作字段与生命周期

仍然只读取磁盘二进制。新增工具 `research/analyze_moments_layout.py` 在读取后先校验
完整核心文件 SHA-256，再从对象虚表定位 GetTypeName 和序列化器，重建常量字符串，
记录字段编号、对象偏移和写入函数调用位置。它不导入 Frida，不附加进程，不执行 ARM
指令，也不调用微信函数。输出为 `research/moments-request-layout.json`。

真实类型名由 GetTypeName 字符串初始化代码还原，字段编号由序列化器的显式参数读取：

| 请求／子对象 | 静态还原的真实类型名 | 已记录的写入调用 |
| --- | --- | --- |
| 发布请求 | `micromsg.SnsPostRequest` | 36 个字段 |
| 互动请求 | `micromsg.SnsCommentRequest` | 3 个字段 |
| 互动分组 | `micromsg.SnsActionGroup` | 6 个字段 |
| 具体互动 | `micromsg.SnsAction` | 22 个字段 |
| 对象操作请求 | `micromsg.SnsObjectOpRequest` | 4 个字段 |
| 单个对象操作 | `micromsg.SnsObjectOp` | 3 个字段 |

这是已识别写入函数的清单，不是完整 `.proto` 定义。尚未覆盖的编码会缺项，尤其发布
结构中仍存在未归类字段；无法从编号反推出原始字段名。JSON 用存储偏移而非猜测名称标记。

### 互动请求和正文

`SnsCommentRequest` 的字段 2 是分组对象，存储于请求对象 `+0x10`；字段 3 位于
`+0x18`，构建器从业务任务 `+0x90` 复制，当前只能归为请求标识字符串候选。

`0x3aeb90c` 构建互动请求，`0x3aec050` 调用之前定位的互动包装层 `0x3aecae8`：

- `0x3aeba00..0x3aeba10` 将帖子模型首个 64 位值写到分组 `+0x08`，对应字段 1。
  第二阶段将其列为帖子 ID 的高可信静态候选；第三阶段已通过列表／详情响应及 XML 的 ID 一致性核对。
- 分组 `+0x18` 和 `+0x20` 分别对应字段 3、4，指向 `SnsAction`；后者只在存在被回复
  对象的条件分支构造，属于回复对象的静态候选。
- `SnsAction` 的字段 5 位于 `+0x28`，由业务任务 `+0x78` 的动作值写入，
  证据为 `0x3aebedc..0x3aebee8`。
- 字段 8 位于 `+0x30`，基类虚函数 `0x3aeb8a8` 从业务任务 `+0x30` 复制字符串。
  该函数通过 `0x3aebc10..0x3aebc20` 的虚调用参与构建，是正文参数的静态候选。
- 同一构建器还填充当前账户、帖子所有者、时间／序号及被回复对象相关数据；这些来源
  不能统一写成固定常量。字段 7 的具体含义、回复关联 ID 和服务器校验条件仍需核对。

### 点赞与取消点赞已进一步区分

点赞方向的静态链路：

```text
菜单动作 0 -> 0x44ae2b8 -> 异步 functor 0x44fc2b8
 -> 第二层 functor 0x44fc7ac
 -> 0x3b9c738（某类帖子分支）
 -> 0x3bc9e08 -> 0x3aeb754 -> 0x3aeb18c（业务任务构造）
 -> 请求构建 0x3aeb90c -> 0x3aecae8 -> command 213
```

`0x3b9c788` 传入动作值 **1**，构造器保存在业务任务 `+0x78`，最终写到
`SnsAction` 字段 **5**。这使“点赞方向使用动作值 1”的判断有业务层赋值证据；
仍未验证所有帖子类别的分支和实际服务器响应。

取消点赞方向的静态链路：

```text
菜单动作 1 -> 0x44ae40c -> 异步 functor 0x44fd29c
 -> 第二层 functor 0x44fd770
 -> 0x3b9d32c（某类帖子分支）
 -> 0x3afa7d4 -> 0x3afa914 -> 0x26aeb5c -> command 218
```

`0x3b9d32c` 的日志标签可静态还原为 `DeleteLikeDataItem`。
`0x3afa80c..0x3afa824` 构造 `SnsObjectOp`，将模型首个 64 位值放在 `+0x08`
（字段 1），将操作值 **5** 放在 `+0x18`（字段 2）；随后加入请求字段 3 的重复列表。
这说明至少在该分支里，取消点赞通过对象操作 **218 / op 5**，不能简单把互动请求
213 的动作值改为 0。分支标签属于静态归因，实际效果尚未动态验证。

### 原生提交层的静态 ABI 候选

三个构建／提交函数均接收 `x0..x4` 五个参数，内部行为一致：`x0` 管理器，`x1` 请求
对象，`x2` 字符串上下文，`x3` 选项对象，`x4` C++ completion 对象。返回 scene 的
`+0x08` 任务编号。这里描述的是静态数据流，不是已验证可调用的函数声明。

| 类型 | Scene 分配大小 | 请求在 Scene 内 | 响应在 Scene 内 | 请求 ctor | 请求 dtor | 请求序列化回调 | 响应解析回调 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 发布 | `0x240` | `+0x78`，大小 `0x1a0` | `+0x218`，大小 `0x28` | `0x5476c1c` | `0x5492494` | `0x3b03ab4` | `0x3b03b74` |
| 互动 | `0xc0` | `+0x78`，大小 `0x28` | `+0xa0`，大小 `0x20` | `0x5476ffc` | `0x54ae8c4` | `0x3af4704` | `0x3af47c4` |
| 对象操作 | `0x110` | `+0x78`，大小 `0x40` | `+0xb8`，大小 `0x58` | `0x5477134` | `0x54b656c` | `0x26b15d4` | `0x26b1694` |

三个提交函数都将 completion 放到 scene `+0x68`，非内联对象存在所有权转移分支；
提交层还通过管理器虚表 `+0x28` 注册任务。不能传空 completion，也不能在请求未结束时
销毁其代码或捕获的对象。现有文字发送的常驻 C++ completion 修复提供了可参考的实现，
但朋友圈场景的签名、对象生命周期及运行线程尚未完成独立验证。

第三阶段继续核对了纯文字发布请求的正文缓冲区、客户端 ID 与私密标志，并在
`0x3b9dac8 -> 0x3af217c` 确认评论业务分支传入动作值 2。发布、点赞、取消点赞和根评论
请求均已通过原生编解码检查，已加入需要单独显式启用的实验 API。
朋友圈媒体上传、完整回复关联与服务器写入行为仍未验收，不能把这些检查视为发布成功证明。
